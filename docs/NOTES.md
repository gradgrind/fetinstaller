Both the Linux and the Windows versions now seem to be running quite smoothly.

There is a German translation to check the translation mechanism. If the underlying system is not German, this can be triggered by setting the environment variable "QTLANG=de".

An annoyance on Windows is that, unlike on Linux, files in use by a running program (including the program itself) cannot be deleted. It might be functionally neatest to use a Powershell script for the uninstaller, as this can be deleted while it is running, but that means a whole new program in a different language with a different GUI. Especially the translations look challenging.

At present the compromise solution is to use a simple Powershell script to copy the uninstaller (with libraries) to a temporary location, run the uninstaller from the temporary location, then, finally, delete the temporary stuff. The C++ uninstaller has code for copying itself, when given the command-line arguments to do this. A second call, this time to the copied version, passing the path to the installation which is to be removed, performs the actual removal. The powershell script then removes the temporary directory.

One thing that needs bearing in mind is that at least one element of the uninstaller process needs to be either external to the installation itself (say, some system utility) or a script which can delete itself. If a script is involved, I suppose the brief console flash is unavoidable. Another problem with Windows is the lack of a fully functional "exec". Any new process will have its own Id, so it cannot really be regarded as a proper continuation of the parent process. In particular, it is difficult to wait for the end of the chain – for the caller the end of the first subprocess is effectively the end of the chain. So perhaps the idea with a Powershell (or cmd) script as the uninstall launcher might be as good as it gets. A single call which returns only when the full job is done is needed for the installer (when it offers to uninstall an existing installation). If this script/program is in the installation directory, it must be deletable.

Of course, for the "normal" uninstaller it is not necessary to have the call block until it has completed, so the chained processes might be alright for this purpose. Alternatively, the calling process (e.g. the installer) could take of the process management itself, if the uninstaller parts can be run separately without further subprocesses.
